# Elemental Trials 도트 이미지 준비 문서

기획서(`Docs/Elemental Trials 기획서.md`)의 "아트, 이펙트, 사운드 가이드"를 그릴 수 있는 목록으로 풀어 쓴 문서다.
수치는 모두 **게임 픽셀(px)** 기준이다. 게임 픽셀 1칸 = 이미지 픽셀 1개 = 1/16 유닛.

> 일정 메모: 그림을 게임에 붙이는 건 3주차다. 지금은 준비만 하고, 1~2주차는 색깔 도형으로 개발한다.
> 그림 준비가 1주차 코드 시간을 먹지 않게 한다.

## 2. 이미지 상세

### 2.1 플레이어

| 항목 | 내용 |
|---|---|
| 크기 | 16 × 16 셀. 몸은 약 10 × 14 px. 피격 판정은 6 × 6 px (기획서), 그림보다 작아야 공정하게 느껴진다 |
| 시점 | 탑다운 3/4 (위에서 비스듬히). 오른쪽을 보는 그림 한 방향만 그리고, 왼쪽은 코드로 좌우 반전 |
| 대기 | 2프레임, 0.5초씩 (숨쉬기: 몸 1 px 위아래) |
| 걷기 | 2프레임, 0.15초씩 (발 번갈아) |
| 피벗 | 발밑 가운데 (Bottom Center) |
| 코드로 처리 (그리지 않음) | 대시 잔상, 피격 깜빡임, 피격 시 붉은 화면, 조준 방향 |

### 2.2 보스: 잿빛 수호자

| 항목 | 내용 |
|---|---|
| 크기 | 그림 48 × 48 px, 셀 64 × 64. 플레이어의 3배 정도로 보여야 위압감이 생긴다 |
| 디자인 | 회색 돌 골렘, 가슴에 코어 구멍 (코어는 별도 이미지). 실루엣은 굵고 단순하게 |
| 대기 | 2프레임, 0.4초씩 (돌 조각이 1 px 들썩) |
| 돌진 | 1프레임 (몸을 앞으로 숙인 자세) |
| 기절 | 2프레임, 0.2초씩 (고개 숙임 + 머리 위 별은 그리지 않고 상태 아이콘으로) |
| 피벗 | 발밑 가운데 |
| 코어 | 8 × 8 흰색 원. 1페이즈 주황, 2페이즈 빨강은 코드로 색을 입힌다. 이미지 한 장으로 두 페이즈를 쓴다 |
| 코드로 처리 | 원형 탄막 예고(코어 발광), 돌진 예고선, 피격 흰색 플래시, 2페이즈 색 변화 |

### 2.3 투사체

| 이미지 | 그림 | 색 |
|---|---|---|
| 플레이어 탄 | 4 × 4 px 마름모, 8 × 8 셀 | 흰색 + 하늘색 테두리 |
| 보스 탄 | 6 × 6 px 원, 8 × 8 셀 | 빨강·자홍 + 어두운 테두리 1 px |

- 탄막 게임에서 가장 중요한 가독성 규칙: **보스 탄은 바닥·플레이어 탄과 색이 절대 겹치지 않게**.
- 바닥 불 장판(주황)과도 구별되도록 보스 탄은 자홍 쪽으로.

### 2.4 타일 (아레나 40 × 22칸, 한 칸 8 × 8 px)

| 이미지 | 내용 |
|---|---|
| 바닥 | 어두운 돌바닥 3종 (기본, 금 간 것, 이끼 조금). 무늬는 아주 약하게 (탄막이 잘 보여야 함) |
| 벽 | 위, 아래, 왼쪽, 오른쪽, 모서리 4개, 안쪽 모서리 4개 (Rule Tile로 자동 연결) |
| 웅덩이 | 영구 웅덩이 3곳. 9칸 조각(가운데 + 테두리 8개)으로 그리면 크기를 자유롭게 만들 수 있다 |

- 아레나 전체 크기는 320 × 176 px (화면 320 × 180에서 위아래 2 px 여백).

### 2.5 UI (HUD)

| 이미지 | 크기 | 메모 |
|---|---|---|
| 스킬 아이콘 5개 | 16 × 16 | 기본 공격, 불덩이, 물결, 번개, 대시. 원소 색이 한눈에 보이게 |

| 상태 아이콘 4개 | 8 × 8 | 화상(불꽃), 젖음(물방울), 대전(번개), 기절 면역(방패) |

## 3. 톤과 색

### 3.1 전체 톤: "어두운 돌 + 선명한 원소"

| 대상 | 톤 | 이유 |
|---|---|---|
| 바닥, 벽, 보스 몸 | 저채도, 어두운 회색·남보라 | 배경이 조용해야 원소와 탄이 보인다 |
| 원소 (불, 물, 번개) | 고채도, 밝게 | 반응을 고르는 게임이라 색이 곧 정보다 |
| 보스 탄 | 자홍·빨강 + 어두운 테두리 | 무조건 피해야 하는 것은 가장 튀는 색 |
| UI | 배경과 같은 어두운 판 + 흰 글자 | 전투 화면을 가리지 않게 |

### 3.2 원소 색 (팔레트에서 이 계열로 고정)

| 원소 | 주색 | 밝은 색 | 쓰는 곳 |
|---|---|---|---|
| 불 | 주황 `#f2561d` | 노랑 `#ffc23d` | 불덩이, 불 장판, 화상 아이콘, 데미지 숫자 |
| 물 | 청록 `#2aa3d6` | 하늘 `#8fe3ff` | 물결, 젖은 바닥, 젖음 아이콘 |
| 번개 | 연보라 `#8c7dff` | 흰노랑 `#fff3a6` | 낙뢰, 전도 경로, 대전 아이콘 |
| 증기 (반응) | 회백 `#c8c8d8` | 흰색 | 증기 구름 |

- 위 색은 시작점이다. 3.3의 팔레트에서 가장 가까운 색으로 맞춘다.

### 3.3 팔레트 하나로 통일

- 기획서 규칙: AI 도트와 pixelfx 이펙트를 **팔레트 하나로** 맞춘다.
- 추천: Lospec의 32색 내외 공개 팔레트 하나를 정한다 (예: Endesga 32, Resurrect 64).
- 정한 팔레트 파일(.hex 또는 .png)을 `Assets/Art/Palette/`에 두고, 모든 이미지를 그 색으로만 다시 칠한다(양자화).
- pixelfx 이펙트는 `--opts '{"palette": [...]}'`로 같은 팔레트의 색을 넣어 렌더한다.

## 4. 도트 한 칸의 크기를 고정하는 법

### 4.1 기준

| 항목 | 값 |
|---|---|
| Pixels Per Unit (PPU) | **16** (모든 이미지 동일, 예외 없음) |
| 화면 해상도 | 320 × 180 (Pixel Perfect Camera) |
| 1080p 모니터 | 정확히 6배 확대 → 도트 1칸 = 화면 6 × 6 픽셀 |
| 타일 | 8 × 8 px = 0.5 유닛 |

- 모든 이미지가 같은 PPU여야 캐릭터와 타일의 도트 크기가 같아 보인다. 이미지마다 PPU가 다르면 도트 크기가 섞여서 어색해진다.

### 4.2 AI 생성 이미지를 진짜 도트로 바꾸기 (가장 중요)

AI가 만든 "도트풍" 이미지는 보통 1024 × 1024 같은 큰 그림이다. 도트 한 칸이 실제 픽셀 수십 개로 되어 있고, 경계가 흐리다. 그대로 쓰면 PPU가 맞지 않고 흐릿해진다.

1. **목표 크기로 생성 요청**: "16x16 pixel art sprite, top-down 3/4 view, no anti-aliasing, hard edges, limited palette, transparent background"
2. **격자 크기 찾기**: 도트 한 칸이 몇 픽셀인지 확인한다 (예: 1024 ÷ 64 = 16 → 64 × 64 도트 그림).
3. **최근접 이웃(Nearest Neighbor)으로 축소**: 목표 크기(예: 16 × 16)로 줄인다. 다른 축소 방식은 색이 섞여서 안 된다.
4. **손으로 정리**: 흐린 테두리 픽셀, 외톨이 점, 반투명 픽셀(알파는 0 또는 255만)을 지운다.
5. **팔레트 양자화**: 3.3의 팔레트 색으로만 다시 칠한다.
6. **확인**: 800%로 확대해서 계단 모양이 깔끔한지 본다.

- 도구: Aseprite(유료, 가장 편함), LibreSprite 또는 Pixelorama(무료)

### 4.3 Unity 가져오기 설정 (모든 도트 이미지 공통)

| 설정 | 값 | 이유 |
|---|---|---|
| Texture Type | Sprite (2D and UI) | |
| Sprite Mode | 한 장이면 Single, 시트면 Multiple | |
| Pixels Per Unit | 16 | 4.1 |
| Mesh Type | Full Rect | 작은 도트는 Tight로 해도 이득이 없고, 가끔 가장자리가 잘린다 |
| Filter Mode | **Point (no filter)** | Bilinear면 도트가 뭉개진다 |
| Compression | **None** | 압축하면 색이 번지고 블록 노이즈가 생긴다 |
| Generate Mip Maps | 끔 | 2D 고정 크기라 필요 없음 |
| Alpha Is Transparency | 켬 | |
| Max Size | 원본 크기 이상 (보통 512 또는 1024) | |
| Pivot | 캐릭터는 Bottom Center, 타일·아이콘은 Center | 발이 바닥에 붙게 |

## 5. Unity 최적화를 위한 이미지 크기

### 5.1 원칙

1. **시트(텍스처) 크기는 2의 거듭제곱**으로: 128, 256, 512, 1024. 실제로 최적화가 일어나는 곳은 텍스처 한 장 단위다.
2. **프레임 칸(셀)도 2의 거듭제곱**으로 맞춘다: 8, 16, 32, 64. 그러면 시트도 자연스럽게 2의 거듭제곱이 된다.
3. **그림은 셀보다 작아도 된다**: 48 × 48 보스는 64 × 64 셀에 넣는다. 셀을 키우지 말고 그림을 셀에 맞춘다.
4. **Sprite Atlas로 묶는다**: 작은 이미지 여러 장을 한 텍스처로 모으면 그리기 호출(draw call)이 줄어든다. 이게 2D에서 가장 큰 최적화다.
5. **같은 그림 여러 장 만들지 않기**: 좌우는 반전(flip), 색 변화는 코드(tint)로 처리한다. 보스 코어·데미지 숫자를 흰색으로 그리는 이유다.

### 5.2 파일별 크기

| 파일 | 셀 | 배치 | 시트 크기 |
|---|---|---|---|
| `player.png` | 16 × 16 | 대기 2 + 걷기 2 = 4칸, 한 줄 | 64 × 16 |
| `player_shadow.png` | 16 × 8 | 1칸 | 16 × 8 |
| `boss.png` | 64 × 64 | 대기 2 + 돌진 1 + 기절 2 = 5칸 → 4열 2줄 | 256 × 128 |
| `boss_core.png`, `boss_shadow.png` | 8 × 8, 64 × 16 | 각 1칸 | 8 × 8, 64 × 16 |
| `projectiles.png` | 8 × 8 | 플레이어 탄, 보스 탄 (+ 2번째 프레임) | 32 × 8 |
| `tiles.png` | 8 × 8 | 바닥 3 + 벽 12 + 웅덩이 9 = 24칸 → 8열 4줄 | 64 × 32 |
| `ui_icons.png` | 16 × 16 | 스킬 5 + 커서 1 | 128 × 16 |
| `ui_small.png` | 8 × 8 | 하트 2 + 상태 4 + 숫자 10 = 16칸 | 128 × 8 |
| `ui_frames.png` | 32 × 32 | 슬롯 테두리, 체력바 조각 | 64 × 32 |
| `title_bg.png` | 320 × 180 | 1장 | 320 × 180 (아래 메모) |
| `title_logo.png` | 256 × 64 | 1장 | 256 × 64 |

- 타이틀 배경은 화면 크기 그대로 320 × 180으로 둔다. 압축을 안 쓰니 2의 거듭제곱이 아니어도 손해가 작다 (약 225 KB). 억지로 512 × 256에 넣으면 오히려 메모리를 더 쓴다.

### 5.3 Sprite Atlas 구성

| 아틀라스 | 넣을 것 | 예상 크기 |
|---|---|---|
| `Gameplay.spriteatlas` | 플레이어, 보스, 투사체, 그림자 | 512 × 512 |
| `Tiles.spriteatlas` | 타일 | 128 × 128 |
| `UI.spriteatlas` | 아이콘, 하트, 숫자, 테두리, 로고 | 512 × 512 |

아틀라스 공통 설정: Filter Point, Compression None, Padding 2, Allow Rotation 끔, Tight Packing 끔.

- pixelfx 이펙트 시트는 크기가 커서 아틀라스에 넣지 않고 따로 둔다 (가져오기 메뉴가 이미 2의 거듭제곱으로 맞춰 준다).

## 8. 이미지 하나 끝낼 때 체크리스트

- [ ] 셀 크기가 5.2 표와 같다 (그림이 셀 밖으로 나가지 않는다)
- [ ] 반투명 픽셀이 없다 (알파 0 또는 255)
- [ ] 팔레트 색만 썼다
- [ ] 흐린 테두리, 외톨이 점이 없다 (800% 확대 확인)
- [ ] 투명 배경이다
- [ ] Unity 설정: PPU 16, Point, Compression None, 피벗
- [ ] 게임 화면(320 × 180)에서 1배로 봤을 때 무엇인지 알아볼 수 있다
