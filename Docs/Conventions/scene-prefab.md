# 씬 · 프리팹 규칙

## 수정 방법
- 씬, 프리팹, .asset YAML 파일은 직접 수정하지 않는다. 에디터(unity CLI)로 수정한다.
  YAML을 직접 고치면 열려 있는 에디터에 반영되지 않고, fileID·GUID가 깨지기 쉽다.
- 수정이 끝나면 씬을 저장한다. 저장 안 된 변경을 남긴 채 작업을 끝내지 않는다.
- 같은 씬·프리팹을 여러 사람이 동시에 수정하지 않는다. 씬·프리팹을 고치는 PR에는 그 사실을 적는다.

## 씬·프리팹 동시 수정 막기
씬(`.unity`)과 프리팹(`.prefab`)은 충돌이 나면 합치기 어렵기 때문에, 누가 어떤 파일을 고치는지 이슈에 남긴다.

팀 규칙
- 이슈를 만들 때 "수정할 씬·프리팹" 칸에 바꿀 파일을 `Assets/`부터 시작하는 전체 경로로 적는다. 없으면 `없음`, 모르면 `미정`.
  `미정`이면 작업을 시작하기 전에 채운다.
- 작업을 시작하기 전에 같은 파일을 적은 열린 이슈가 있는지 보고, 있으면 담당자와 먼저 순서를 정한다.
- 작업이 끝나 PR이 머지되면 이슈를 닫는다. 닫힌 이슈의 파일은 다시 수정할 수 있다.

### 씬·프리팹 수정 전 확인 (Claude)
씬이나 프리팹을 고치기 전에 아래를 확인하고, 결과와 수정할 내용을 보고한 뒤 **사용자가 진행하라고 할 때만** 수정한다.
1. 같은 파일을 바꾸는 열린 PR
   `gh pr list --state open --json number,title,author,files`의 결과에서 `files[].path`가 **고칠 파일의 전체 경로와 정확히 같은** PR을 찾는다.
2. 같은 파일을 "수정할 씬·프리팹"에 적은 열린 이슈
   `gh issue list --state open --search "\"<전체 경로>\" in:body" --json number,title,assignees,body`
   검색은 부분 일치라서, 결과의 `body`에 전체 경로가 정확히 들어 있는 이슈만 겹치는 것으로 본다.
3. 보고 형식
   - 고칠 씬·프리팹(전체 경로), 바꿀 내용
   - 겹치는 PR·이슈 (번호, 제목, 담당자). 없으면 `없음`
- gh를 쓸 수 없거나 저장소가 GitHub가 아니면, 확인하지 못했다고 알리고 같은 방식으로 지시를 기다린다.

## 파일 위치
| 대상 | 위치 |
|---|---|
| 씬 | `Assets/Scenes/<기능>/<씬이름>.unity` |
| 프리팹 | `Assets/Prefabs/<기능>/` |
| 머티리얼 | `Assets/Materials/<기능>/` |

## 오브젝트 이름
- PascalCase로 쓴다: `Player`, `EnemySpawner`
- 좌우가 있는 부위는 `Left`/`Right`를 앞에 붙인다: `LeftArm`, `RightHip`
- `GameObject (1)`, `Cube` 같은 기본 이름을 그대로 두지 않는다.
- 예외: 씬 루트를 묶는 정리용 빈 오브젝트는 `--- Environment ---`처럼 쓴다 (아래 "계층 구성" 참고).

## 계층 구성
- 루트에는 로직(스크립트, Collider, Rigidbody/CharacterController)을 둔다.
- 보이는 부분은 자식 `Model` 아래에 모은다. 애니메이션이나 연출이 루트 이동과 섞이지 않게 하기 위함이다.
  ```
  Player                 ← 스크립트, CharacterController
  └ Model                ← 시각 요소 루트 (출렁임, 기울기)
    ├ Body
    ├ Head
    │ └ LeftEye / RightEye
    ├ LeftShoulder       ← 회전축 (빈 오브젝트)
    │ └ LeftArm
    └ LeftHip            ← 회전축 (빈 오브젝트)
      └ LeftLeg
  ```
- 관절처럼 회전하는 부위는 빈 오브젝트를 회전축으로 두고, 그 아래에 모양을 붙인다.
- 비균일 스케일(예: 0.5, 0.4, 0.3)을 가진 오브젝트 아래에 다른 오브젝트를 붙이지 않는다. 자식이 찌그러진다.
- 장식용(모양만 내는) 프리미티브에 자동으로 붙는 기본 Collider는 지운다.
  히트박스, 트리거, 래그돌처럼 충돌이 필요한 자식 Collider는 남긴다.
- 씬 루트를 정리용 빈 오브젝트로 묶는다: `--- Environment ---`, `--- Characters ---`, `--- UI ---`

## 프리팹
- 아래 중 하나에 해당하면 프리팹으로 만든다.
  - 두 곳 이상(여러 씬, 여러 개)에서 쓴다.
  - 런타임에 생성(Instantiate)한다.
- 씬에 놓인 프리팹을 고쳤다면, 모든 곳에 반영할지(Apply) 이 씬에만 둘지(Override) 정하고 PR에 적는다.
- 비슷한 변형은 복사하지 말고 Prefab Variant로 만든다.
- 프리팹을 Unpack하지 않는다. 꼭 필요하면 이유를 PR에 적는다.

## 참조
- Inspector 참조는 프리팹 내부 오브젝트끼리 연결한다. 씬 오브젝트를 프리팹에서 직접 참조할 수 없다.
- 씬마다 다른 참조(카메라, 매니저 등)는 런타임에 찾거나 초기화 메서드로 넘겨받는다.

## 머티리얼
- URP/Lit 셰이더를 기본으로 쓴다.
- 같은 색·재질은 머티리얼 하나를 공유한다. 오브젝트마다 새로 만들지 않는다.
- `New Material.mat` 같은 기본 이름을 그대로 두지 않는다: `<대상>_<용도>.mat` (예: `Player_Body.mat`)
  - 나눌 용도가 없으면 대상만 쓴다: `Ground.mat`
