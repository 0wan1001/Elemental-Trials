# 이슈 작성

1. 종류 정하기: 기능 / 버그 / 작업
2. 중복 확인: 같은 내용의 이슈가 이미 있는지 검색한다.
   `gh issue list --state all --search "<핵심 키워드>"`
   비슷한 이슈가 있으면 번호와 제목을 보여주고, 새로 만들지 기존 이슈에 덧붙일지 묻는다.
3. 템플릿 확인: `.github/ISSUE_TEMPLATE/`의 템플릿 형식과 제목 머리말을 따른다.
   - 기능 `feature.md` → `[feat]`, 버그 `bug.md` → `[fix]`, 작업 `task.md` → `[chore]`
   - 템플릿이 없으면 사용자에게 알리고, 어떤 형식으로 쓸지 묻는다.
4. 내용 채우기: 사용자의 말에서 채울 수 없는 항목은 지어내지 말고 질문한다.
   - "수정할 씬·프리팹"은 항상 묻는다. 다른 사람과 같은 파일을 동시에 고치지 않기 위한 칸이다.
     답은 `Assets/`부터 시작하는 전체 경로로 받는다. 바꿀 씬·프리팹이 없으면 `없음`, 아직 모르면 `미정`.
   - 스크린샷이 필요하면 파일 경로를 알려주고, 사용자가 등록된 이슈 화면에 끌어다 놓게 한다 (gh로는 이미지를 올릴 수 없다).
5. 라벨과 담당자
   - 라벨: `Docs/Conventions/labels.md`를 따른다. 기능 `feat`, 버그 `fix`, 작업 `chore`
   - 담당자: 실행한 사람 (`--assignee @me`)
   - 저장소에 해당 라벨이 없으면 만들지 말고 사용자에게 알린다 (`gh label list`로 확인).
6. 등록 전에 제목, 본문, 라벨, 담당자를 사용자에게 보여주고 확인을 받는다.
7. 확인을 받으면 아래 명령으로 등록하고 링크를 알린다.
   `gh issue create --title "..." --body "..." --label <라벨> --assignee @me`
