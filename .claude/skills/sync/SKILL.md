# 최신화 · 충돌 해결

## 1. 준비
- 현재 브랜치가 `prod`(또는 `main`), `develop`이면 멈춘다.
- 커밋 안 된 변경이 있으면 먼저 커밋할지 사용자에게 묻는다. 사용자 확인 없이 stash하지 않는다.
- 반영할 브랜치를 정한다 (`Docs/Conventions/git.md` 참고).

  | 상황 | 반영할 브랜치 |
  |---|---|
  | 작업 브랜치에 최신 배포 버전을 받고 싶을 때 | `prod` |
  | 작업 브랜치에서 `develop`으로 보낸 PR에 충돌이 있을 때 | `develop` |
  | `develop`이 없는 저장소 | `main` |

  - 어느 쪽인지 불분명하면 묻는다.
  - `develop`을 반영한 작업 브랜치는 `develop`으로만 PR을 보낸다. `prod`로 보내지 않는다.
- Unity 에디터가 이 프로젝트를 열고 있으면, 머지가 끝날 때까지 **에디터를 닫거나 에디터 창을 클릭하지 말라고** 사용자에게 안내한다.
  머지 중인 파일에는 충돌 표시가 들어가는데, 에디터가 이를 임포트하면 씬이 깨지거나 `.meta`가 새로 만들어질 수 있다.

## 2. 반영
`git fetch origin` 후 `git merge origin/<반영할 브랜치>`
- 이미 push한 브랜치는 rebase하지 않는다 (강제 push가 필요해지기 때문).

결과는 둘 중 하나다.
- **충돌 없음**: git이 머지 커밋까지 자동으로 만든다. 4번(검증)으로 간다.
- **충돌 있음**: git이 머지를 멈추고 충돌 파일을 남긴다. 3번으로 간다.

## 3. 충돌 해결
충돌 파일 확인: `git diff --name-only --diff-filter=U`

| 파일 | 처리 |
|---|---|
| `.cs` 등 코드 | 양쪽 변경을 읽고 둘 다 살리는 방향으로 합친다 |
| Unity YAML (`.unity`, `.prefab`, `.asset`, `.mat`, `.anim`, `.controller` 등 `.gitattributes`에 `unityyamlmerge`로 지정된 파일) | 직접 합치지 않는다. Unity Smart Merge가 설정돼 있으면 2번의 `git merge` 때 이미 자동으로 시도됐고, 여기 남은 것은 자동으로 못 합친 파일이다. 양쪽에서 무엇이 바뀌었는지 설명하고, 어느 쪽을 쓸지 사용자에게 묻는다 |
| `.meta` | 직접 고르지 않는다. GUID가 바뀌면 참조가 끊기므로, 차이를 보여주고 사용자에게 묻는다 |
| 문서, 설정 | 양쪽 내용을 합친다 |

- 한쪽 파일을 통째로 고르는 `git checkout --ours/--theirs <파일>`은 다른 쪽 변경을 **전부 버린다**. 쓰기 전에 무엇이 사라지는지 사용자에게 알린다.
- 판단이 어려운 충돌은 추측하지 말고 묻는다.
- 충돌 표시(`<<<<<<<`, `=======`, `>>>>>>>`)가 남아 있지 않은지 확인한다.
- 해결한 내용(파일별로 어떻게 합쳤는지)을 사용자에게 보여주고 확인을 받는다.
- 확인을 받으면 해결한 파일을 `git add`하고 `git commit`으로 머지 커밋을 만든다 (기본 메시지 사용).

## 4. 검증
- Unity 프로젝트면 에디터에서 다시 임포트한 뒤 `unity recompile`로 컴파일 오류가 없는지 확인한다.
- 충돌을 해결한 씬·프리팹은 에디터에서 열어 오브젝트와 참조가 정상인지 확인한다.

## 5. 보고
- 반영한 브랜치와 커밋 수
- 충돌 여부. 충돌이 있었다면 파일별로 어떻게 해결했는지
- 검증 결과

## 하지 않을 것
- 요청 없이 push하지 않는다.
- `git merge --abort`, `git reset --hard`로 작업을 되돌리기 전에 사용자에게 묻는다.
